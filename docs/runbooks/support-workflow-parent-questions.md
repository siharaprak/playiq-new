# Runbook: Parent Questions Support Workflow

This document details the support workflows for resolving parent queries and issues during the PlayIQ beta phase. This runbook is an extension of the support operations system, aligning directly with the `support_issues` database table schema.

---

## 1. Scope & Categories

We classify parent inquiries under three categories:
*   **`parent_access`**: Issues related to parent dashboard login, viewing child profiles, or linked-child mapping issues.
*   **`privacy_security`**: Inquiries about data safety, student logs visibility, or privacy boundaries.
*   **`billing_beta_policy`**: Queries regarding payment checkout, beta duration, subscription plans, or Stripe.

---

## 2. Roles, Escalation, & SLA Alignment

To maintain operational consistency with the [Beta Support Master Runbook](beta-support-runbook.md), this workflow adheres to the following:

*   **Support Owner**: Project Owner
*   **Escalation Owner**: Project Owner
*   **Triage Targets**:
    *   **P1 (Core path blocked)**: Best-effort response within 8 hours. Escalated directly to the Project Owner.
    *   **P2 (Single user feature block)**: Best-effort response within 12 hours.
    *   **P3 (General query)**: Best-effort response within 24 hours.

---

## 3. Privacy Boundaries & Safety Regulations

All support actions must strictly follow child privacy and access safety parameters:

*   **Access Boundaries**:
    *   **parents cannot access proof files** under any circumstance.
    *   **parents cannot receive proof signed URLs** to download student uploads.
    *   **parents cannot inspect raw tutor/assistant instructions** created by students.
    *   **parents cannot inspect raw AI prompts/responses/logs** generated by students.
    *   Parents receive safe, high-level summaries only (such as node mastery counts and overall course progress metrics).
*   **Unsafe Asks**:
    *   Never ask any parent for passwords, magic links, session tokens, or child account credentials.
*   **Billing Questions Guidance**:
    *   All parent questions about billing or payment checks must receive the following response: **The PlayIQ pilot is a free invite-only beta and Stripe/payment disabled/deferred policy remains active.** Paid checkout and Stripe payment elements remain disabled.

---

## 4. Triage and Diagnosis Procedures

### Case A: Parent Linked-Child Missing (`parent_access`)
1.  **Look Up Linkage Record**: Verify the database `parent_child_links` contains a matching entry for the parent UUID and student UUID.
2.  **Invite Code Verification**: If linkage is missing, instruct the parent to have their student check their dashboard for the correct association details or refer to [Onboarding Support Workflow](support-workflow-onboarding-issues.md).

### Case B: Privacy Concerns Escalation (`privacy_security`)
1.  **Immediate Intake**: Document the parent's query without exposing any internal student identifiers.
2.  **Escalate**: Send high-priority concerns to the Project Owner for direct review. Do not disclose private access metrics.

### Case C: Payment / Stripe Errors (`billing_beta_policy`)
1.  **Reassure Parent**: Clarify that no credit card details are requested for the free invite-only beta. Stripe/payment disabled/deferred policy is enforced.
2.  **Troubleshoot Forms**: If a stripe check page erroneously displays, confirm the student registered via the correct free invite flow.
